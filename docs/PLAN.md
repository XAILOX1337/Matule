# Matule — план реализации

Тренировка по конкурсному заданию «Профессионалы-2026», компетенция «Разработка мобильных приложений».

Рядом лежат:

- `docs/DESIGN_NOTES.md` — разбор макета Figma: токены, компоненты, экраны, навигация;
- `docs/figma/` — скриншоты макета.

## 1. Что требуется

- Android-приложение **«Matule»**: магазин «описаний» (схем) для машинного вязания и проекты пользователя. **minSdk 33** (Android 13).
- Бэкенд — PocketBase, только REST API по выданной спецификации OpenAPI (Swagger).
- **Три отдельных проекта:** библиотека UIKit с демо-проектом, где показаны все состояния компонентов; сетевая библиотека; приложение, которое использует обе через абстракции.
- Clean Architecture (DOMAIN / DATA / PRESENTATION), SOLID, DRY, KDoc-комментарии в библиотеках.
- Git: на каждый спринт отдельная ветка → Pull Request в `main`.
- Регламент: 18 часов, 3 дня, 6 спринтов (≈ 3 ч на спринт).

## 2. Текущее состояние (`MatuleClothes-main`)

Что есть: Kotlin + Jetpack Compose, один модуль `:app`, minSdk 33 / targetSdk 36, AGP 8.13.2, Kotlin 2.0.21, Gradle 8.13.
`SplashScreen` рисует градиент и надпись «Matule». `Color.kt` уже содержит палитру Matule.
В `libs.versions.toml` объявлены Hilt, KSP, Navigation Compose и kotlinx-serialization, но в сборку они не подключены.

Что поменять:
1. **Чужой UIKit** `com.github.AlexeyNerobeev:uikit:1.0.2` (JitPack) подключён ради шрифта SF Pro. По заданию UIKit нужен свой, а чужая библиотека на чемпионате будет считаться готовым решением. Удаляем её, шрифты кладём в свой UIKit.
2. Папка не под git — модуль Г требует ветки и PR.
3. Нет библиотек и слоёв. Тема лежит в приложении, а должна быть в UIKit.
4. `com.example.matuleclothes` и название «MatuleClothes»: приложение должно называться «Matule», а `com.example.*` не пропустит стор. Сразу меняем applicationId, например на `ru.<фамилия>.matule`.
5. Сплэш показывается без таймера и перехода. В макете градиент «от углов к центру», а в коде вертикальный — сверить.
6. В `Color.kt`/`Theme.kt` остались куски шаблона (Purple80…, dynamic color, тёмная тема). В макете тёмной темы нет.
7. Пакет `presentation/Splash` назван с заглавной буквы — переименовать в `splash`.

## 3. Архитектурные решения

### 3.1. Репозиторий: один git, три Gradle-проекта

```
Matule2026/                  ← корень git (сейчас это MatuleClothes-main)
├── MatuleUIKit/             ← проект 1
│   ├── uikit/               ← android-library: тема, шрифты, иконочный шрифт, компоненты
│   └── showcase/            ← демо-приложение: все компоненты во всех состояниях
├── MatuleNetwork/           ← проект 2
│   └── network/             ← android-library: клиент, запросы, модели, ошибки
├── Matule/                  ← проект 3: приложение (текущий код переезжает сюда)
│   └── app/
└── docs/
```

Библиотеки подключаем к приложению через **composite build**: в `Matule/settings.gradle.kts` пишем
`includeBuild("../MatuleUIKit")` и `includeBuild("../MatuleNetwork")`, в `app` — `implementation("ru.matule:uikit:1.0")`.
Каждая библиотека остаётся отдельным проектом и открывается в Android Studio сама по себе. Приложение всегда собирается из актуальных исходников, а эксперт собирает всё из репозитория без лишних шагов.
Запасной вариант, если потребуют бинарник: собрать `.aar` и положить в `Matule/app/libs/`.

### 3.2. Стек

| Задача | Выбор | Зачем |
|---|---|---|
| UI | Jetpack Compose (Material3 только как база) | уже в проекте |
| Навигация | Navigation Compose 2.9, маршруты `@Serializable` | маршрут можно сохранить и восстановить последний экран |
| DI | Hilt + KSP | уже в toml |
| Сеть (внутри библиотеки) | Retrofit + OkHttp + kotlinx.serialization | спрятаны за интерфейсами библиотеки |
| Картинки | Coil 3 | загрузка и дисковый кэш (нужен для кэша главной) |
| Хранение | DataStore Preferences + JSON-файл кэша главной | сессия, PIN, черновики, последний экран |
| Биометрия | androidx.biometric | «Вход по паролю или биометрии». `MainActivity` → `FragmentActivity` |
| Фоновые задачи | WorkManager | уведомления через 1 и 3 минуты |
| PDF | `android.graphics.pdf.PdfRenderer`, без сторонних библиотек | политика конфиденциальности внутри приложения |
| Аналитика | AppMetrica SDK (Яндекс) | модуль Е |
| Тесты | JUnit, MockWebServer | валидаторы, маппинг ошибок сети |

Список библиотек заранее согласовать с Главным экспертом — так требует раздел 2 задания.

### 3.3. Слои приложения (документ «Clean Architecture»)

Правило зависимостей: `presentation → domain ← data`. Domain — чистый Kotlin, без `android.*`.

```
ru.<фамилия>.matule/
├── common/          // Result, DispatcherProvider, расширения
├── domain/
│   ├── model/       // User, Profile, Promotion, Product, Category, CartItem, Order, Project
│   ├── repository/  // интерфейсы: Auth, Profile, Catalog, Cart, Order, Project, Session, Pin, AppState
│   ├── usecase/     // Login, Register, GetHome, SearchProducts, AddToCart, ChangeCartCount, MakeOrder, CreateProject…
│   └── validation/  // EmailValidator, PasswordValidator — чистые функции, покрыть тестами
├── data/
│   ├── remote/      // *RemoteDataSource (интерфейсы) + адаптеры над сетевой библиотекой, мапперы DTO → domain
│   ├── local/       // DataStore: сессия, хэш PIN, черновик профиля, последний экран, настройки; кэш главной
│   └── repository/  // *RepositoryImpl
├── presentation/
│   ├── navigation/  // маршруты, NavHost, сохранение и восстановление последнего экрана
│   ├── common/      // ErrorHost (SnackBar из UIKit), UiEvent, BaseViewModel
│   ├── splash/  auth/login/  auth/profile/  auth/password/  pin/create/  pin/enter/
│   └── main/home/  main/catalog/  main/product/  main/cart/  main/projects/  main/projectcreate/  main/profile/  main/document/
└── di/              // Hilt-модули
```

Требование «сетевой слой вызывается только через абстракцию» закрываем в двух местах:
- библиотека наружу отдаёт только интерфейсы (`AuthService`, `CatalogService`…) и фабрику, а реализации у неё `internal`;
- в приложении ViewModel видит только use case'ы, domain — только интерфейсы `*Repository`, data — свои интерфейсы `*RemoteDataSource` и адаптер к библиотеке.

Замена сетевой библиотеки затронет только адаптеры в `data/remote`.

Слой представления — MVVM: ViewModel + `StateFlow<UiState>` + одноразовые события. В документе рекомендован MVP, но это рекомендация, а для Compose стандарт — MVVM. Обоснование — в презентации.

## 5. Где легко потерять баллы — самопроверка

- Каждый экран сверить с макетом: отступы по шкале 4–48, размеры шрифтов, цвета, скругления. Нет больших пустот, ничего не обрезается на маленьком экране и при крупном шрифте.
- «Далее», «Сохранить», «Подтвердить» неактивны, пока поля пустые или невалидные.
- ViewModel не вызывает сеть напрямую — только через use case и репозиторий.
- KDoc везде в библиотеках. Нет дублей: PIN-клавиатура, карточки, хэдер — компоненты UIKit.
- Выключить интернет и пройти все экраны: везде должен появляться SnackBar с кнопкой закрытия.
- После каждого спринта — PR в `main`. В ветке лежат исходники, а не архив.

- Код пишу прямо в папке проекта. Собрать проект у себя я не могу: из моего окружения закрыт доступ к Maven и Google-репозиториям, эмулятора нет. Поэтому сборка и запуск — у тебя в Android Studio, а ошибки и скриншоты присылаешь мне.
- Локальные коммиты могу делать я. Push и Pull Request — ты.
